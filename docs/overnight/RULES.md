# Overnight rules (binding for every N-prompt)

Read this file first, then the prompt. If the prompt and this file disagree, this file wins.

## Working agreement
1. **Chain.** Prompts form tracks. Each prompt says which `[Nx] DONE` it follows. Before starting, read `docs/AGENT_STATE.md` (on the previous branch). If the previous prompt wrote `DONE`, base your new branch on that branch's tip. If it wrote `BLOCKED` or nothing after 12 hours of checking every 10 minutes, base on its last good commit and say so. Record the base sha in your `START` line.
2. **Local only.** New local branch and worktree per prompt. **Never push.** Never merge into `integration/v2-waves`: Claude merges after review. Append `[Nx] START <sha>`, `[Nx] STEP <what> <sha>`, `[Nx] DONE <sha>` / `[Nx] BLOCKED <reason>` lines to `docs/AGENT_STATE.md`.
3. **Never wait for a human.** Undecided: take the safe option, write it down in the report, continue. Time-box every item; at the box's end, record the item as PARKED with the reason and move on.
4. **Honesty over green.** Never loosen a gate, threshold, check, guard or verdict policy to make something pass. Status vocabulary: `READY_TO_SERVE_CANDIDATE` (the final word belongs to an independent check), `SHADOW_ONLY`, `REVIEW_ONLY`, `PARKED`, `NOT_POSSIBLE`. Never call a bank ready. Report every NOT RUN item with the reason.
5. **Gates (unchanged).** Detection correct on 100 percent of a folder's readable files and zero cross-bank false accepts; at least 90 percent hold-out yield (VERIFIED or REVIEW with rows read); where printed balances exist at least 80 percent VERIFIED; a fresh spec-independent audit (up to 40 VERIFIED files: dated lines vs rows, balance chain recomputed, first/last balance vs printed anchors) with no disagreement.
6. **Regression.** Before every commit that touches shared code or any spec: new tests, the statement-engine suite, `app.main` import smoke. After every 3 changes and at the end: a seeded corpus compare of at least 600 files from the 15 baseline banks plus au_sfb, bank_of_maharashtra, airtel_pb (previous tip vs current): status, bank, layout, rows and verdict must be identical (**0 diffs**) unless the prompt expects a named change. A difference: find the commit, revert it, park the item.
7. **Marker rules.** No bank marker shorter than 7 characters, never a bare IFSC prefix, own-bank evidence only from header/footer text, never narration. A marker contained in another bank's longer marker is not evidence (registry rule). `test_marker_collisions.py` must keep passing; cross-bank check (up to 10 files from every other folder) before committing any marker.

## Data and safety
8. **No PII anywhere** you write or print: bank ids, counts, sha8 only. No statement text, narration, names, account numbers, amounts, dates, file names or paths in commits, docs, logs, screenshots or tests. Committed tests use synthetic PDFs. The sha8-to-path manifest stays in a gitignored local file. Never open `passwords.txt`; locked files are counted, not opened. **No OCR.** Corpus is read-only. No secrets in output.
9. **Protected stacks.** Do not stop, restart, rebuild or reconfigure `airco_*`, `keycloak*`, `ue_*`, `demo_*`. Only the `onb_*` stack may be rebuilt, and only by prompts that say so. Record container ids and uptime before and after.
10. **Resources.** Shell calls last about 170 s; long jobs run in resumable chunks with a state file. 2 CPUs. Parallelise read-only analysis only.

## Ownership
11. **Default ownership.** The engine (`extraction/*`), `checks.py`, registry logic, the verdict policy, the completeness and mismatch guards, `serve.py`, `process_statement` and legacy parsers belong to Claude. A prompt may explicitly delegate a named piece; that delegation is on a branch only and is never merged by you. Outside the delegation, do not touch them.
12. **Delegated engine work rules (only where a prompt says so).** The new capability must be (a) opt-in per `LayoutSpec` through a new field whose default leaves every existing spec's behaviour byte-identical, or a regex/rule widening that you prove changes nothing on the 600-file compare; (b) covered by unit tests, including negative and mutation tests (a changed amount, a dropped row, a swapped side, a truncated page must never end VERIFIED); (c) unable to raise a verdict: it may turn FAILED or no_layout into REVIEW or VERIFIED only through the existing independent checks; (d) documented in `docs/engine/` with the exact rule, the limits and the files it was derived from (sha8).
