# Demo PDFs (N9) — fully synthetic, zero real data

Every file here is generated by `tools/final/gen_demo_pdfs.py` (per-spec layout,
Helvetica text PDF via pikepdf). Holder is always **Test Holder**; account
numbers, IFSCs, references and amounts are invented; each statement's printed
balance chain is internally consistent so the independent checks can run.

| file | bank | expected on rc (serve mode, 20-bank list) |
|---|---|---|
| `demo_<bank>.pdf` ×20 | each served bank | detected as its bank; VERIFIED where the spec prints anchors, honest REVIEW elsewhere (see `gen_results.json`) |
| `demo_locked_hdfc.pdf` | HDFC | `PASSWORD_REQUIRED`; password = **`demo1234`** (deliberately in this README for the demo) |
| `demo_scanned.pdf` | — | image-only page → `UNSUPPORTED` (scanned, no text) |
| `demo_truncated_canara.pdf` | Canara | statement stops mid-table → refused or REVIEW, never VERIFIED |
| `demo_wrongbank.pdf` | HDFC header | detect as HDFC; if overridden to a different bank the job must FAIL (mismatch guard), never produce a wrong-bank VERIFIED |
| `demo_unknown.pdf` | — | marker-less generic text → `UNKNOWN` row ("could not tell which bank"); picker offers servable banks; a mismatched pick fails honestly |

Local generation results (`gen_results.json`): 6 VERIFIED + 13 REVIEW +
1 honest FAILED (`paytm` — the synthetic shape defeats both paytm spec
variants; keep it in the kit as the demo's honest-failure file).

No real customer content exists in this directory — safe to show on screen.
